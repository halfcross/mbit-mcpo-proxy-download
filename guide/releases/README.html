On this page

Release notes (public download releases) ​

Customer-facing release notes for MindBehindAI are stored here and published to the public download repo (halfcross/mbit-mcpo-proxy-download) on every semver tag. The desktop app shows this text when an update is available.

File naming ​

One file per release: docs/releases/X.Y.Z.md (semver without v, matching the tag vX.Y.Z).

Language ​

English only. No German or mixed copy in these files.

What to include ​

Write for people using the app, not for developers.

IncludeExclude
New integrations or catalog entries users can addRefactors, internal architecture
UI or workflow changes in the shellCI, tests, build scripts
Connection, login, or setup improvements users noticeDependency or toolchain bumps users do not see
Fixes for problems users might have hitMCP submodule updates unless tools or behavior in the app change
Breaking changes and what to doInstall commands, download-page steps (shown in the app UI instead)
Links to the private app repo, commit SHAs, auto-generated commit lists

Structure ​

Notable user-facing release ​

markdown
Short summary sentence.

## What's new

- Bullet one
- Bullet two

## Fixes

- Plain-language fix

Use Improvements or Breaking changes sections only when needed.

Patch / maintenance release (nothing major) ​

A single sentence is fine:

markdown
Bug fixes and stability improvements.

Do not invent improvements or duplicate the version number in every bullet.

Checklist before git tag ​

  1. Bump electron-app/package.json version if needed.
  2. Add or update docs/releases/<version>.md in the same commit (or PR).
  3. Read the file aloud: would a business user care about every line?
  4. Push the tag; CI fails if the file is missing or contains forbidden boilerplate.
