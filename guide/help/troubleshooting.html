Troubleshooting ​

Work through the symptom that matches yours.

macOS quarantine (“damaged” or “can’t be opened”) ​

Release .dmg files are not notarized. Browsers tag downloads with quarantine, so Gatekeeper may block the app until you clear it or use the install script.

Recommended: one-line install (download + copy + quarantine) ​

bash
curl -fsSL https://halfcross.github.io/mbit-mcpo-proxy-download/install.sh | bash

The script downloads the latest .dmg from GitHub Releases, copies MindBehindAI to Applications, and clears quarantine on the app bundle.

Manual install (drag from .dmg) ​

  1. Download the .dmg from Releases or the download page.
  2. Open the disk image and drag MindBehindAI to Applications.
  3. If macOS says the app is damaged or cannot be opened, remove quarantine once (adjust the path if needed):
bash
APP="/Applications/MindBehindAI.app"
find "$APP" \( -type f -o -type d \) -exec xattr -c {} + 2>/dev/null
find "$APP" -type l -exec xattr -c -s {} + 2>/dev/null

Avoid plain xattr -cr on this bundle: it follows symlinks, and bundled Node’s bin/npx / npm / corepack point into lib/node_modules/…. If that subtree is absent for one architecture, xattr reports “No such file” and may fail the whole command. On macOS, xattr -c -s clears extended attributes on the symlink inode (-s); do not use -h here — with BSD xattr, -h prints help, not “don’t follow”.

You can also try System Settings → Privacy & Security → Open Anyway once after the first launch attempt.

Windows — SmartScreen, slow start, and Defender ​

MindBehindAI for Windows ships as a portable .exe (no installer). Builds are not code-signed yet, so Windows may show extra warnings and scan the app heavily on first launch. That is expected and safe if you downloaded from the official release page.

SmartScreen (“Windows protected your PC” / unknown publisher) ​

  1. Download only from GitHub Releases (or the download page link that points there).
  2. Double-click MindBehindAI-<version>-portable-x64.exe.
  3. If SmartScreen blocks the app: click More info → Run anyway.

There is no separate “Trust publisher” step until the app is signed with a commercial certificate. Self-signed certificates do not remove this warning for public downloads.

First start feels slow (10–30 seconds, no window) ​

The portable file unpacks a large bundle (assistant bridge, runtimes, optional agent tools) into your user temp folder. Microsoft Defender often scans that folder at the same time, which can take 20–30 seconds on the first run after download.

  • Second and later starts of the same version are usually much faster (same unpack folder is reused).
  • In Task Manager, you may see Antimalware Service Executable with high CPU during this phase—that is normal.

If the app seems to run but no window appears, reset saved window position:

  1. Quit MindBehindAI (tray icon → Quit, or end the task in Task Manager).
  2. Delete %APPDATA%\MindBehind\mcp-orchestrator\shell-ui-prefs.json.
  3. Start the portable .exe again.

Recommended Microsoft Defender exclusions (optional, IT-friendly) ​

Adding exclusions is optional but often cuts first-start time and repeated scans. Use only paths you trust (official download). Replace <YourUser> with your Windows sign-in name and <version> with the release you installed (for example 5.2.3).

What to excludePath or itemWhy
Portable app (file)Folder where you saved the .exe, e.g. C:\Users\<YourUser>\Downloads\MindBehindAI-<version>-portable-x64.exeAvoids rescanning the download on every launch
Unpack folder (folder)%TEMP%\MindBehindAI — typically C:\Users\<YourUser>\AppData\Local\Temp\MindBehindAIPortable edition extracts the bundle here
App data (folder)%APPDATA%\MindBehind\mcp-orchestrator — C:\Users\<YourUser>\AppData\Roaming\MindBehind\mcp-orchestratorSettings, license storage, logs, connection config

Steps (Windows 11; Windows 10 is similar):

  1. Open Settings → Privacy & security → Windows Security → Virus & threat protection.
  2. Under Virus & threat protection settings, choose Manage settings.
  3. Scroll to Exclusions → Add or remove exclusions → Add an exclusion.
  4. Add the File (your .exe), then Folder entries for %TEMP%\MindBehindAI and %APPDATA%\MindBehind\mcp-orchestrator as above.

If your organization uses Defender for Endpoint or another antivirus, ask IT to allow the same paths or the process MindBehindAI.exe under your standard software-request process.

Windows UI notes ​

  • The app uses a custom title bar (like macOS), not the classic File / Edit / View menu inside the window.
  • Quit is available from the tray icon (notification area) if the window is closed.

Bridge will not start ​

  1. On Home, read the Built-in engine step—if it says unavailable, reinstall or contact support with the exact text.
  2. Check Logs for address already in use—another program is using the HTTP port. Change Settings → HTTP port or quit the other program.
  3. Tap Apply changes on Home after large edits under Connections.

Tools missing in MBIT Chat ​

  1. Confirm the bridge is Running on Home.
  2. Confirm each connection is enabled under My connections.
  3. Re-run Sync enabled connections on Integrations → MBIT Chat after editing connections.
  4. For manual setup, re-copy each Copy link—URLs change if you rename a connection.

OAuth loops or expired login ​

  1. Clear Settings → OAuth tokens, then trigger sign-in again from your assistant so the browser opens fresh.
  2. Make sure pop-up blockers are not blocking the Telekom or Microsoft login window.

Docker-required preset fails ​

Install Docker Desktop and wait until it is healthy, then retry the preset. The bridge itself does not run inside Docker.

Agents (experimental) — first start slow or fails ​

The Agents feature (enable under Settings → Experimental) runs Paperclip via the official CLI on first start: bundled npx paperclipai run (same family as npx paperclipai onboard --yes). State lives under your MindBehind data directory, not inside the .app / portable bundle.

What to expect ​

  • First start after enabling Agents: downloads from the npm registry (internet required). Use Start on the Agents page; open View logs to see progress. Duration depends on network speed and npm cache.
  • Later starts reuse the Paperclip instance config and database under paperclip/ and should be much faster.

Install fails or hangs ​

  1. Confirm internet access to the npm registry (corporate proxies may block registry.npmjs.org).
  2. Read the last lines on the Agents page error box or Logs → Agent company.
  3. Quit the app. If support asks you to reset, delete the Paperclip data folder (not the whole app data tree):
    • macOS: ~/Library/Application Support/MindBehind/mcp-orchestrator/paperclip (path may vary slightly by edition)
    • Windows: %APPDATA%\MindBehind\mcp-orchestrator\paperclip
  4. Start Agents again.

On Windows, Defender may scan heavily while npm writes under %APPDATA% and the user npm cache; see Windows Defender exclusions if IT allows path exclusions. The app starts Paperclip via bundled node.exe + npx-cli.js (not a separate Command Prompt window).

MindBehindAI sets PAPERCLIP_OPEN_ON_LISTEN=false so Paperclip does not open your default browser; use the Agents tab instead.

Design (experimental) ​

Enable under Settings → Experimental → Design. The app downloads the upstream project into app data, installs what it needs, and starts the local web UI on a free port. You do not need to install package managers or Git yourself for the default path (GitHub archive + bundled Node/npx).

On first Design start, the app also downloads a matching Node.js 24 toolchain into your MindBehind data folder (internet required, larger download). That runtime is only used for Design, not for the assistant bridge.

Requirements ​

  • Internet for the first download and dependency install.
  • A valid license is required to save settings and start.

What to expect ​

  • First start can take several minutes. Use Workspace → Design → Start; open View logs or Logs → Design for live output.
  • OpenCode ships with MindBehindAI; the Design dev process gets that binary on PATH, so agent detection should list it without a separate install. If the UI still says “available to install”, click Rescan after the server is running (or restart Design once). For Open Web UI–backed models, save URL, API key, and OpenCode model id under Integrations → Open Web UI (the same fields as for Agents); Design uses them when the Design experimental toggle is on. The small Next.js / Turbopack dev corner widget is hidden in the embedded Design webview after the first successful project setup (config patch in the downloaded repo).
  • If the status stays on Starting… while logs already show a Web: URL and the site opens in an external browser, fully quit MindBehindAI and try Start again once; the app now uses a local network check that should not be affected by HTTP(S) proxy settings on your Mac.
  • If the web view does not load, check the error line on the Design page and confirm nothing else is blocking the chosen port (the server logs the port it uses).

If download fails ​

Non-GitHub upstream URLs fall back to git clone when git is available. If both archive download and git fail, install Git and retry, or check your network and corporate proxy.

Native module / SQLite errors after an app update ​

If logs mention NODE_MODULE_VERSION or better_sqlite3.node compiled for a different Node, quit the app, delete
…/open-design/repo/node_modules/.mb-design-native-abi
under your MindBehind data directory, then start Design again so dependencies can be rebuilt for the current Design Node runtime.

Still stuck ​

Collect three things before contacting support:

  1. A screenshot of Home (status strip visible).
  2. The last ~30 lines from Logs.
  3. Your OS and version (macOS: Apple Silicon or Intel; Windows: edition and 64-bit).
