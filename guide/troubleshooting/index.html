Troubleshooting ​

Find your issue below. Each section explains what you see, why it happens, and how to fix it.

Docker issues ​

Docker Desktop is not installed ​

What you see: The Dashboard shows a red DOCKER indicator and the message "Docker Desktop is not installed."

Fix:

  1. Click Install Docker Desktop — MCPBehindIT downloads and installs it for you.
  2. Or download it manually from docker.com and install it yourself.
  3. After installation, click Re-check on the Dashboard.

Docker Desktop is installed but not starting ​

What you see: MCPBehindIT detects Docker but can't start it. The message says "Docker Desktop was found but could not be started."

Fix:

  1. Open Docker Desktop manually from your Applications folder or Spotlight.
  2. Wait until the Docker icon in the menu bar shows it's running (the whale icon stops animating).
  3. Return to MCPBehindIT and click Re-check.
  4. If Docker Desktop won't start, try restarting your Mac.

Docker auto-install failed ​

What you see: The progress bar stopped and shows an error message.

Fix:

  1. Check your internet connection.
  2. Click Re-check to try again.
  3. If it keeps failing, install Docker Desktop manually from docker.com.

Docker is running but MCPBehindIT shows "Unavailable" ​

What you see: Docker Desktop is clearly running, but MCPBehindIT doesn't detect it.

Fix:

  1. Make sure Docker Desktop has fully started (wait for the whale icon to stabilize).
  2. Click Re-check on the Dashboard.
  3. If using Colima or another Docker-compatible runtime instead of Docker Desktop, check that the Docker socket is at the default path (/var/run/docker.sock).

Port issues ​

Port already in use ​

What you see: The port check fails with a message like "Port 8000 is already in use."

Fix:

  1. Option A: Find and stop whatever is using port 8000. In Terminal:

    bash
    lsof -i :8000

    Then stop that process.

  2. Option B: Change the gateway port in Settings → HTTP port to an unused port (e.g., 8001).

TIP

If the MCPBehindIT container itself is already running on that port, the app recognizes this and treats it as OK. This only happens when something else is using the port.

macOS issues ​

"MCPBehindIT is damaged and can't be opened" ​

What you see: macOS shows a warning that the app is damaged.

Fix: Open Terminal and run:

bash
xattr -cr "/Applications/MCPBehindIT.app"

This clears the quarantine flag. MCPBehindIT uses ad-hoc code signing since it's not distributed through the App Store.

"MCPBehindIT can't be opened because Apple cannot check it for malicious software" ​

Fix: Same as above — run the xattr -cr command. Or: right-click the app in Finder → Open → click Open in the dialog.

License issues ​

"License validation failed" ​

What you see: The activation overlay shows "License validation failed."

Fix:

  1. Double-check your license key — no extra spaces at the beginning or end.
  2. Make sure you have an internet connection.
  3. If the key was already activated on another device, contact MindBehind IT.

License expires while the app is running ​

What you see: The gateway suddenly stops and the activation overlay reappears.

Fix:

  1. If your license was renewed, paste the new key and click Activate.
  2. If you think this is an error, click Check again — the validation server may have been temporarily unreachable.
  3. Contact MindBehind IT if the issue persists.

OAuth issues ​

OAuth toast appears but browser didn't open ​

What you see: The "OAuth sign-in required" notification appears, but no browser window opened.

Fix:

  1. Click Copy URL on the toast.
  2. Paste the URL into your browser manually.
  3. Complete the sign-in process.
  4. This can happen on some macOS configurations where opening external URLs is restricted.

OAuth keeps asking to sign in ​

What you see: Every time you restart the gateway, the OAuth toast appears again.

This is normal for the first restart after token expiry. OAuth tokens have a limited lifetime. When they expire, the gateway requests a new authorization.

If it happens on every restart even shortly after signing in:

  1. Check Logs for errors related to the OAuth token exchange.
  2. Make sure the service (e.g., Teleconsole) is properly authorized for your account.
  3. Verify your system clock is correct (token validation is time-sensitive).

Gateway issues ​

Gateway won't start ​

What you see: Clicking Start doesn't work or shows an error immediately.

Fix:

  1. Check that Docker is running (green DOCKER indicator).
  2. Check the port is available.
  3. Look at the error details on the stack card.
  4. Check Logs for container startup errors.
  5. Try Apply & Restart to force a fresh container.

"Successfully connected" but tools don't work in my AI client ​

Fix:

  1. Verify the server appears on the Clients tab.
  2. Copy the OpenAPI URL and open it in your browser — you should see a JSON spec.
  3. Make sure your AI tool is configured with the correct URL.
  4. If using Open WebUI, use localhost instead of 127.0.0.1.

Still stuck? ​

  1. Check Logs for any error messages.
  2. Enable Advanced mode in Settings and review the generated config.
  3. Try stopping the gateway, waiting 10 seconds, and starting it again.
  4. Restart Docker Desktop.
  5. Contact MindBehind IT support with your log output and config (from Advanced mode).
